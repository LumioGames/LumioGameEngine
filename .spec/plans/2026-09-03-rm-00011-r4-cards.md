## 产品背景与已锁决策（为什么这么改）
- **账号已在线可顶号**（ADR-057 第 5 条）：r3 深审 P1-4——Runtime `EntityBindingQuery.Admit` 对「账号已在线」与「形状错误」同返 `invalid_binding_shape`，宿主分不清该顶号还是拒绝，只好自建 `account_sessions` 表，两表分叉后账号永久卡死。裁决：C-2′ 加一个独立结局，宿主删表全问 Runtime。
- **roomId = 宿主路由键**（ADR-058 §11）：Owner 定「一个进程一个 World Manager 一个 GameWorld，世界与事件内部没有 Room 概念；多房间 = 多个服务器进程 + 匹配路由（Unreal 专用服务器方案）」。契约字段名保留（wire 兼容），语义改为「宿主把连接路由到哪个 Game 实例」；`cross_room` 由宿主路由层判定，Runtime 接口按实例隐含。
- **创建记录**（ADR-058 §3）：客户端 World 收「世界变化」三种记录（创建 / 字段变化 / 销毁）同一条有序流，创建优先；创建记录 = EntityType + NetEntityId + 全部可见字段当前值。C-1 现有 `entity.identity` 普查块升为创建记录语义。
- **上行两种**（ADR-058 §6，参照 Unity Netcode）：`Authority.Owner` 字段改 `.Value` 自动上行；动作走 `[ServerRpc]`。两者都是 InputCommand 信封的种类。C-1 现有 `chat.input` 就是 `ChatComponent.SendMessage` 这条 ServerRpc 的线上形态，`chat.event` 就是 `OnChatMessage` 这条 ClientRpc；本轮新增一个通用 `field.write` 上行种类给 Owner 字段用（样板示例的改名走它）。
- **NetEntityId 128 位**（ADR-058 §16）：= 世界实例 ID（64）+ 世界内计数器（64），世界发号、不随机。C-2 已是 32-hex 字符串不用改；**C-1 `chat.event` 的 `senderNetEntityId` 现为 `u64`（LumioBinV1 定宽），装不下 128 位**——必须改为 16 字节定宽（两个 u64：instanceId, counter，小端），这是本卡必须升级确认后落实的字段类型变化（Owner 已在 ADR-058 §16 拍板 128 位，本卡按此改，交回物注明影响 Client 解码 / Game oracle，由 R4-04 / R4-06 消费）。
- **证据 = 日志**（ADR-057 第 3 条）：不再有证据包；oracle 只读服务器日志 + 客户端日志；sha 以行尾归一化后的字节计算。
- **dev-run**（ADR-057 第 11 条）：架构仓收口命令仍启动 CI 红的 C# mvp-host，改为启动 Rust 宿主。

## 详细要求
