## ECS 定稿（ADR-058 Draft，2026-09-03）

结构已定，见 [ADR-058](../decisions/ADR-058-ecs-world-manager-and-annotation-registry.md)（18 条裁决）与 [`ecs.md`](../knowledge/features/ecs.md) M1a / M2 / M3 / M4 / M8 / M9 / §4.5 样板示例。一句话：一进程一个 World Manager 一个 GameWorld（多房间 = 多进程）；组件类是唯一真源，一个生成命令产三件；同步字段 = `Sync<T>(scope, authority)`，上行参照 Netcode（Owner 字段自动上行 + `[ServerRpc]`），事件 = `[ClientRpc]` 无历史；一套源码按端拆 partial 文件编两份程序集；组件式写法 + 生成模板内联存储；绑定 = 实体字段 + 派生索引；NetEntityId = 实例 ID + 计数器由世界发号；恢复 = 从快照建新世界；客户端直接引用 Runtime ECS。

## 共同执行规范

沿用 r3 蓝图「共同执行规范」全文，并追加两条硬禁令：
- **不得修改验收尺子**：`verify-evidence.mjs` 判定逻辑、Rust acceptance 断言、Fixture 口径只能按 ADR-057 改动，验收失败时改尺子 = 退回。
- **不得跨仓冒名**：任何进程内执行的代码必须来自该进程所属仓；不得经 `DOTNET_STARTUP_HOOKS` 或等价机制注入他仓代码产出证据。

## R4-05 卡片正文（Runtime 单一世界，按 ADR-058）

- **拥有范围**（LumioGameRuntime）：`modules/ecs`——World Manager（`Create` / `CreateFromSnapshot` / `Enqueue` / `OwnerThread` / `Tick` / `Get<T>` / `Each<T>` / `Single<T>`）、公开 ECS API（现全 internal）、`Sync<T>`（struct）/ `SyncList<T>` / `SyncDict<K,V>`、标注 `[EcsComponent]` / `[Persist]` / `[ServerOnly]` / `[ClientOnly]` / `[EntityType]` / `[Has]` / `[Child]` / `[ServerRpc]` / `[ClientRpc]`、九回调（含 PostAttribute）、128 位发号（实例 ID + 计数器）、WorldEntity + `WorldSaveComponent`、快照含 `[Persist]` 字段 + 身份表 + 发号器 + WorldEntity + Tick；`modules/replication`——删 `EntityBindingQuery` 两世界与 `_values`，改为 Manager 服务（准入 / AttributeId 薄适配 / ingress），删 `_eventsByRoomTick` / `_displayed` / `SetMessage` 旁路，每 Tick outbox，`Authority.Owner` 上行 + ServerRpc / ClientRpc 分发，同 Tick 按发送者 NetEntityId 排序；生成器——`gen-declarations` 扩为一句命令产三件（`Registry.g.cs` / `Sync.g.cs` / `attribute-declarations.json`）+ MSBuild 目标 + 零 diff 测试 + lint（`[ServerOnly]` 只许在 `*.Server.cs`）；删 `Ingress/ChatIngressWorld.cs`；持久化按 `[Persist]`。
- **前置**：R4-01 合入（C-2′ roomId 语义 / 账号已在线结局；`roomSequence` 措辞）；ADR-058 Draft。
- **不做**：多房间、开发期世界热重载（只留 `CreateFromSnapshot` 入口）、Unity 端。
- **验收 4 条**：见上表 R4-05 行。
