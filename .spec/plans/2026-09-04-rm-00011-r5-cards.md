## 产品背景与已锁决策（为什么这么改）
- **包上网线（ADR-060 第 1 条）**：Runtime 的 `WorldManager` 已按样板产出「欢迎 / 创建（带字段值）/ 字段变化 / 销毁 / ClientRpc」包，但 C-1 只有 r2 的 `FullSnapshot` 普查 + `chat.event`，宿主与客户端只能各自重编、反拼，形成两套复制模型。Owner 定：C-1 就是这个包的网线形态，`FullSnapshot` / `Delta` / `entity.identity` / `chat.event` 删除，聊天事件 = `ChatComponent.OnChatMessage` 这条 ClientRpc 的记录。

- **admit 不回 id（ADR-060 第 9 条）**：C-2 `admit` 同步回 `netEntityId` 迫使 Runtime 在登录里自己 `Tick()`。改为只回受理 / 拒绝，id 与连接代数由 `Welcome` 交付；删 `listBindings`。

## 产品背景与已锁决策（现状 → 裁决，逐条对应源码）
- **存储（ADR-060 第 11 条）**：现 `World.cs` 字典 + `EntityRecord.Components[]`，`Get<T>()` 顺序扫；每 `Sync<T>` 一个 `SyncSlot<T>` 堆对象；`EntityRecord.Lifecycle` 探针 List 长在生产实体上。→ 生成模板类（实体 + 组件一起分配、入池复用）、定位表零查找、`Sync<T>` 值内联、密集数组、探针搬出。
- **观察者（第 4 条）**：现 `WorldManager._session`（连接 → id）、`_knownToClients` 全局集合、`World.TryReadConnected` 按字段名 / 反射读游戏组件。→ 引擎 `ObserverComponent`（四字段），Manager 按类型读；包按观察者 NetEntityId 寻址；Manager 无连接字符串容器。
- **投影（第 3 / 5 / 6 / 7 条）**：现 `StampAndProject` 全局「已发」集合、`Hydrated` 跳过、`Destroys` 写死空数组、`Scope` 不裁、`creates` 死代码。→ 每观察者一包：`ProjectedTick = 0` 时先 `Welcome` + 全量创建（WorldEntity 第一，每包至多 `createsPerPack` 条按优先级），之后增量；创建与字段变化同一 Scope 规则；销毁进包；墓碑按计数器推导，快照只存下一个号。
- **准入（第 9 条）**：现 `EntityBindingQuery.Admit / Expire / Spawn` 自己 `_manager.Tick()`；`EntityBindingQuery.Create()` 写死实例 ID 兜底；`TryParseLoose`。→ 准入只下单 + 写 `ObserverComponent`，id 在提交相发号并产生 `Welcome`；删三处自 Tick、兜底构造、`TryParseLoose`。
