## 背景

当前优先打通逻辑位姿到客户端表现位姿的最小闭环。讨论使用玩法例子和直白语言，遵守“如无必要，勿增实体”：现在确定会影响后续结构的数据归属与接口边界，平滑参数和复杂边界留给验证。

必须分清三件事：双 Transform 是逻辑与表现的职责划分；确认 / 预测双 World 是 GAS 的预测方案；逻辑 / 表现实体现有归属是实体模型问题。不能为解决其中一件事，未经决定就新增另一套 World 或实体。

本轮用户说的 **Local** 是“客户端与服务器在本地运行、复用 CS 代码”的运行方式，不自动等同于文档里的 Local Entity 或某个 `Mode.Local` 枚举。

### 术语澄清：预测重算、对象重建与断线重连

用户追问“重建是服务器还是客户端重连”，并再次强调“第一性原则，如无必要，勿增实体”。这里记录术语澄清，不将提问视为接受任何重建或表现保管方案。

- **客户端预测校正 / 重算**：正常联网期间也会发生。服务器告诉客户端已经处理了哪些输入及相应权威逻辑状态，客户端据此恢复预测所需的逻辑基准，再经 GAS 重放尚未确认的输入，得到当前逻辑结果。服务器本身继续向前模拟，不因客户端猜错而重建。
- **预测 World 整体克隆**：这是 ADR-064 第 8 条当前 Draft 采用的具体实现形态，可能导致旧对象 / 句柄失效；它不是“预测校正”这个行为本身必然要求的形式，更不是双 Transform 自动要求新增 World。本文未冻结是否必须每包丢弃旧对象再整体克隆。
- **客户端断线重连**：连接恢复后重新握手、接收全量状态并恢复客户端会话 / 世界。它与普通联网纠偏不同；服务器实体是否保留按 B05 的会话约定，不因客户端重连自动重建服务器世界。
- **服务器故障恢复**：快照 / 流水恢复属于另一个问题，不属于本轮 Transform 讨论。

此前助手沿用整体克隆草案，直接推荐 Client 增加表现保管关联，用户未接受该结构。后续 D26 已选择复用接收权威同步的既有客户端实体承载 Model，通过完整位姿样本驱动；普通预测副本替换不搬运模型。具体逻辑恢复方式仍独立比较，不能只凭“原地恢复”四个字就宣称它一定更简单，也不能只因草案写了整体克隆就视其为必需。

已确认要求仍然成立：既有角色身份和表现应连续、逻辑到表现单向、权威应用与必要重算完整成功前不发布中间状态、无 adoption / ID remap。没有批准新增表现 World、模型 Entity 或独立表现状态表。

## 决策：已确认

以下是逐轮讨论已确认的结论；Q 区保留其余未决建议及已关闭子项的原编号入口。

| 编号 | 已确认结论 | 具体含义与理由 |
| --- | --- | --- |
| D01 | LogicTransform 管逻辑，ModelTransform 管客户端表现，单向流动 | 碰撞、射线、范围判定、AOI 和业务读取逻辑位姿；渲染使用 ModelTransform，平滑和动画结果不反写逻辑。 |
| D02 | 同一个角色实体承载两种职责，不额外建模型 Entity 或表现 World | 角色的 ModelTransform 是该角色的客户端数据。服务器、联网客户端、本地运行 CS 都遵守这个划分；纯客户端对象仍遵守现有 Local Entity 规则。 |
| D03 | 本地控制先响应预测，远端实体按服务器样本平滑 | 本地摇杆移动经 GAS 预测，动画及时响应。服务器结果到达后先校正逻辑并重放未确认输入，Model 再消除剩余误差，同时继续正常移动；不直接追一个过时的服务器坐标，不因每次纠偏重启动画。 |
| D04 | LogicTransform 位置采用 32 位 Float，Model 也用浮点 | 用户选择 Float，未采用定点数；角色连续移动，可移动 0.1 米或更小距离，不按整格取整。世界规模尚未固定，不能据此承诺任意距离下的精度或跨平台物理逐位一致。 |
| D05 | 1 世界单位 = 1 米；最小体素格为 1 米立方 | 体素索引用整数，不限制实体只能走整数米。固定 Tick 步长不等于固定小数精度。 |
| D06 | 首期逻辑缩放固定为 1，物理尺寸由碰撞形状参数定义 | Model 可以有表现缩放；影响玩法与碰撞的动态缩放不在首期展开。 |
| D07 | 每个实体当前有唯一的位姿控制者，技能向它提交移动意图 | 普通移动由移动控制器结合输入与碰撞后写 LogicTransform；物理接管时由物理担当写入者。同一写入者在一个 Tick 内可合法连续更新，不是一帧只能写一次。请求可以当场处理，让后续业务读到已移动的位置。框架权威应用另有受控入口。 |
| D08 | 启动期检查互相竞争的写入配置 | 同类角色同时配置普通移动与物理接管，却没有明确互斥规则，应直接报错。运行期仍需统一受控入口；没有批准另造“写冲突就让整 Tick / World 停机”的专项机制，具体处理留 Q02。 |
| D09 | 只发布完整逻辑结果，不向渲染泄漏可变 ECS 引用 | 客户端权威应用和预测重放共同成功前，不能发布中间状态。渲染循环消费值 / 只读样本，不在渲染循环里重跑玩法 Tick。具体发布时间和元数据留 Q03。 |
| D10 | Teleport 必须显式调用，跳过插值 | A 点到 B 点用专门 TP / Teleport 入口；逻辑更新并携带跳变语义，表现清掉旧平滑历史后立即到位，保留实体与模型。不能仅凭移动距离猜测 TP；明确挂接的子节点跟随父 TP，并清理继承链的旧平滑。重复、迟到与重放规则留 Q04。 |
| D11 | 坐骑 / 车座挂接与站在移动平台上是两类关系 | 坐骑与座位使用明确挂接；电梯 / 船上的人仍能走、跑、跳，支撑关系不自动带来父子销毁归属。平台先更新逻辑，角色唯一控制器综合平台运动、自身输入与碰撞。 |
| D12 | 移动平台同步并平滑相对位姿，先平台后乘客 | 样本带平台实体 ID 及人的相对位置、旋转；先得到平台 Model，再平滑人的相对偏移，最后组合世界 Model，避免把继承的平台运动再做第二遍世界坐标平滑。具体时间轴仍留 Q03。 |
| D13 | 平台跟随考虑旋转；跳起继承接触点速度 | 船旋转时，脚下位置的运动不只来自平移。起跳继承接触点速度（含旋转贡献），离地后独立运动，落地后重新建立支撑；具体碰撞库和求解器不在此冻结。 |
| D14 | 逻辑重建应保持同一已有角色的表现连续性 | 不能仅因逻辑句柄重建就让模型消失、动画重播；同类型、同位置、同参数的不同实例不得误合并，表现键不能默认唯一。D26 后续确定 Model 归属既有客户端实体；具体样本身份与失效接口仍见 Q02 / Q04。遵守无 adoption / ID remap。 |
| D15 | 先交付 Transform 必需合同与最小闭环 | R-00460 不等待九项能力全部设计完成。先用 C# Host 验证，再明确浏览器 / WASM 消费要求；R-00470 的通用 VFX、重放副作用扩展与双 Transform 最小闭环分期。 |
| D16 | 子节点记录父引用与局部位姿，框架维护派生子列表 | A 背 B 时，B 记录父 A 与相对位姿；A 的只读子列表由框架维护，不另立关系真值。挂接 / 换父 / 解绑经统一入口一致更新；单父节点、禁止成环。详细规则见已关闭的 Q04.1。 |
| D17 | 父先子后更新，逻辑读取及时，挂接默认保世界位姿 | A 更新后，框架由父位姿与 B 的局部位姿得到 B 的世界位姿，后续业务读到新结果；派生计算不算第二个业务写入者。上背需指定挂点与位移方式，瞬间对齐遵守显式跳变；逻辑不依赖客户端动画骨骼。 |
| D18 | 断线不自动解绑；真正销毁按存活关系清理 | A / B 断线但服务器实体仍在时保持关系；A 销毁默认解绑并保留存活 B 的世界位姿，B 销毁则只从 A 子列表移除；双方销毁统一清理。AOI 不可见不当作服务器销毁。“随父销毁”显式启用，背负玩家默认不选；放下 / 落地策略归玩法与物理。 |
| D19 | 子实体数量从只读子列表取得，乘员人数按玩法定义筛选 | 查询当前已生效的直接子实体及数量；简单车辆以直接挂车的角色为乘员，货箱等不计入人数。不另存手工增减的人数真值；容量由服务器上车准入检查，并考虑已接受但未结算的请求。查询方法名与完整座位规则未冻结，详见已关闭的 Q04.2。 |
| D20 | 位姿、移动状态与动画状态分属各自职责 | LogicTransform 管逻辑位姿；同一角色的移动控制组件管理速度、着地、移动模式等必要运动状态；ModelTransform 及平滑逻辑管显示位姿，动画系统管播放进度。纠偏从同一逻辑基准恢复必要运动状态再重算，纯动画不中断；物理接管时速度复用物理这一来源。具体字段和恢复方式未冻结，详见已关闭的 Q02.1。 |
| D21 | 远端表现正常插值，断样短暂外推，到上限停止，恢复后平滑纠偏 | 有有效速度时在上限内延续 Model，无适用速度则等待；外推不进入逻辑碰撞，显式 TP 立即到位。本地 GAS 预测独立处理。用户确认策略，未冻结 100ms 测试起点或统一误差参数，详见已关闭的 Q03.1。 |
| D22 | 同一客户端共用平台显示位姿，本地乘客的相对移动及时响应预测 | 每个平台每个渲染帧一份 Model，乘客均在其上组合；本地相对移动用预测结果，远端相对移动插值 / 有界外推。接受远端平台显示延迟随组合传给乘客，逻辑碰撞仍用 LogicTransform；具体时间映射未冻结，详见已关闭的 Q03.2。 |
| D23 | TP 标记随位姿保留，新跳变只消费一次，直接接上最新完整结果 | 普通移动保留最近有效跳变标记；新跳变清旧平滑历史，重复不重复清理，迟到旧位姿不能拉回。已合并的 TP 后移动直接显示最新结果；标记布局及 GAS 预测 / 权威操作关联仍未冻结，详见已关闭的 Q04.3。 |
| D24 | 父数据可用时相对跟随，不可用时世界位姿兜底，恢复后平滑切回 | 仅子实体仍获准可见时由服务器提供派生世界位姿，不改变逻辑挂接关系。父模型未加载但位姿可用仍正常组合；父恢复后保住当前世界 Model 再接回，明确 TP 例外。具体投影与参考表示接口未冻结，详见已关闭的 Q04.4。 |
| D25 | 每次写位置前检查当前控制者，越权拒绝并明确报错 | 用户明确采用此表述。结合 D07，同一控制者仍可合法连续更新；检查在本次位姿修改前完成。具体控制权表示、错误码及框架故障分类未冻结，不据本次确认增设整 World 恢复机制，详见已关闭的 Q02.2。 |

### D12 的平台例子

人站在电梯中，电梯上升，人同时向右走。逻辑层先推进电梯，再由人的移动控制器算出人相对电梯的移动。表现层先得到本帧电梯的显示位置，再把平滑后的相对偏移放到这部电梯上。

首期逻辑缩放为 1 时，位姿组合的含义如下；这是数学说明，不是已冻结的 API 或矩阵存储布局：

```text
人的世界位置 = 平台位置 + 平台旋转作用于人的相对位置
人的世界旋转 = 平台旋转组合人的相对旋转
```

平台 ID 与相对位姿必须描述同一次完成的逻辑结果；依赖顺序不靠网络包到达顺序碰运气。仅在同一参考实体内直接插值相对偏移；切换支撑或离地时要保住当前世界表现，再转换参考坐标，不能把两个不同平台的局部坐标直接 Lerp。

### 不能直接照搬的推断

- 第 3 页把 Sweep 描述为不受速度 / 时间影响、不会隧穿，表述过强。沿路径扫掠有助于检测障碍，但初始重叠、动态 / 旋转障碍、查询精度和迭代上限仍需处理；不能把一条线性 Sweep 当作完整物理求解保证。
- 第 7 页按最新 velocity 外推，仍然无法知道尚未收到的急停或转向。必须有时间 / 距离边界；新权威结果到来后修正表现，不得把外推位置用于逻辑碰撞。这里的远端表现外推也不同于 GAS 逻辑预测。
- 第 7 页 `Lerp(currentValue, targetValue, 平滑系数)` 若按渲染帧固定系数调用，60Hz 与 120Hz 的收敛速度不同。应按实际帧时间定义平滑；已经做过时间插值的结果再全程低通会增加延迟，需说明第二次平滑只消除什么误差，也不能对继承的平台运动重复平滑。
- 第 5 页位置差量的 10bit 估算只覆盖约 0..1000 的非负量。若每轴需要表达正负 10 米、精度 0.01 米，就是 -1000..1000 共 2001 个值，至少 11bit；三轴已是 33bit，尚未计掩码等开销。17 字节不能直接作为新方案的包长验收承诺。
- 旧稿的发送帧号来自 owner，不能未经映射就当作服务器 Tick 或本机渲染时间；网络到达时间也不能代替采样时间。事件触发的稀疏发送与“缓存用尽就停住”直接组合，会让本应匀速运动的角色反复停顿，需同时定义有效期 / 补样策略。

- [Unity 6.0 Transform](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Transform.html)：`position` / `rotation` 是世界位置 / 四元数旋转，另有 `localPosition` / `localRotation` / `localScale`、只读双向矩阵、方向轴、点 / 向量 / 方向转换以及父子查询和更新方法。

- [Godot 4.5 Node3D 定义](https://github.com/godotengine/godot/blob/4.5/doc/classes/Node3D.xml)：`position` 是父坐标系位置，`global_position` 是世界位置；提供局部 / 世界 Transform3D、四元数、欧拉角、缩放、`to_global` / `to_local`、旋转 / 朝向等基础面。其默认角度为弧度，默认前向为 -Z，与 Unity 的部分约定不同；不混用两套默认值。
- [Unity lossyScale](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Transform-lossyScale.html)：非均匀父缩放与子旋转组合会产生剪切，世界缩放三元数只能近似表达；完整变换以矩阵为准。

**建议基础面**：以下名称为语义草案，不冻结 C# 类型、参数顺序或全部重载。Logic / Model 使用一致的坐标词汇，分别读取逻辑和显示数据；写入者仍按各自职责受控，不增加另一套 Entity 或 Transform 生命周期。

| 类别 | 建议能力 | 约束 |
| --- | --- | --- |
| 位置 | `WorldPosition`、`LocalPosition`；对应世界 / 局部更新入口 | 挂接后含义不变，写世界位置统一反算局部真值 |
| 旋转 | `WorldRotation`、`LocalRotation`；世界 / 局部欧拉角便捷接口 | 四元数为旋转表示，欧拉角由其换算；便捷角度建议按 Unity 使用度，旋转顺序与底层弧度转换在公共数学合同中明确，不存两份旋转真值 |
| 缩放 | `LocalScale`、只读 `LossyWorldScale` | Model 支持表现缩放；D06 下 Logic 首期恒为 `(1,1,1)`，可派生常量而不增加存储，非单位逻辑缩放请求拒绝；Lossy 不承诺任意父子组合下精确可逆 |
| TRS 与矩阵 | 组合 / 读取局部 TRS、`SetLocalTRS`、`LocalMatrix`、`LocalToWorldMatrix`、`WorldToLocalMatrix`；复用数学库的 TRS 建矩阵能力 | 矩阵由有效 TRS 与父链派生，缓存由框架维护；不独立同步 / 存档另一份可写矩阵；不可逆时逆变换明确失败，不返回伪造的单位矩阵 |
| 坐标转换 | `TransformPoint` / `InverseTransformPoint`、`TransformVector` / `InverseTransformVector`、`TransformDirection` / `InverseTransformDirection` | 点包含平移、旋转、缩放；向量包含旋转与缩放；方向仅旋转且保持原长度，按 Unity 对应方法语义区分 |
| 方向与常用操作 | `Forward`、`Up`、`Right`；`Translate`、`Rotate`、`RotateAround`、`LookAt`；世界 / 局部位置与旋转的组合设置 | 方向轴从旋转派生；增量操作明确 World / Local，复用同一受控更新入口；不代替碰撞求解，也不绕过显式 Teleport |
| 父子关系 | `Parent`、`Root`、`ChildCount`、子枚举 / `GetChild`、`IsChildOf`、`SetParent` / 解绑 | 复用 D16-D19 的父引用与派生索引、默认保世界位姿及循环检查，不新增关系真值或改变 ECS 创建序规则 |

**统一读写语义草案**：读取明确区分 `WorldPosition` / `WorldRotation` 与 `LocalPosition` / `LocalRotation`；控制者写入使用含坐标空间含义的入口，例如 `SetWorldPose` / `SetLocalPose`。不能让一个无说明的 `Position` 因为有无父节点而改变坐标空间。暂不增加与它们同义的无前缀别名。

- 没有父节点时，局部位姿与世界位姿一致；挂接时，世界位姿由当前有效的父逻辑位姿与子局部位姿组合得到。
- 写局部位姿直接更新该唯一真值；写世界位姿时，框架用当前有效的父逻辑位姿反算局部位姿再更新同一真值。两种入口都受 D25 保护，不暴露两套可独立赋值的 Sync 位置。
- 例子：车无旋转，世界 X=100 米，乘员局部 X=1 米，则乘员世界 X=101 米。控制者将乘员世界 X 更新到 102 米，框架换算其局部 X=2 米，父关系保持不变。父有旋转时按同一规则进行逆变换，不由玩法重复实现公式。
- 换算使用 LogicTransform 的父位姿，不使用父 ModelTransform；Model 中同名的世界 / 局部含义仍指显示位姿，不能作为逻辑换算来源。父先子后的有效读取继续遵守 D17。
- 这些入口负责接受控制者已解算的位姿，坐标换算不替代碰撞、支撑或导航计算。普通更新沿正常平滑语义，瞬间位移仍须显式 Teleport；不能因方法名有 Set 就自动判定 TP，也不能省掉明确跳变标记。
- 组合设置先完成该次调用的校验，再更新位姿，避免位置已变但旋转 / 缩放被拒；不借此新建通用业务事务。非有限值、无效旋转以及不可逆矩阵按公共数学 / 错误合同明确处理。
- 普通 Model 父子矩阵按有效层级组合保留完整仿射结果；存在非均匀缩放时，不用近似的世界旋转与 LossyWorldScale 重拼来替代完整世界矩阵。世界矩阵任意反解 / 写回不是首期必备入口，避免承诺所有剪切矩阵都能无损拆成局部 TRS。
- D12 / D22 的支撑跟随仍按已确认的平台位姿与相对运动处理；Model 表现缩放不自动改变逻辑支撑偏移、碰撞尺寸或运动速度。基础数学能力齐全不等于首期开放逻辑动态缩放。

**替代与成本**：只保留少量位置 / 旋转入口会把基础坐标运算留给各玩法重复实现，与 D28 的完整基础面要求不符。按成熟引擎组织基础 API，成本主要是复用数学库、派生矩阵缓存、统一写入入口和必要数学验证；不整套移植 Unity GameObject 或 Godot Node 生命周期，也不为每个派生属性增加同步存储。只读派生的世界属性与经换算写入局部真值的方法并不矛盾。

**确认状态**：完整基础能力方向已由 D28 明确；以上成员、角度便捷约定与写入签名作为 API 草案在整体设计稿中统一审阅，不逐项要求用户选择常规方法。D06 缩放边界保持有效；世界 / 局部统一换算的具体合同不因参考文档存在就视为已经实现。

#### Q04.1 A 背 B：父子关系维护（已确认，问题关闭）

用户追加的具体问题：A 背着 B 时怎么更新逻辑 Transform、记录和查询谁挂了谁；A 下线、A 销毁或 B 销毁时怎么办。用户在本组说明后回答“可以，没问题”，确认以下规则，记入 D16-D18。保留 Q04.1 编号供旧引用定位；不表示 Q01 / Q02 / Q04 的其余机制或六组建议已整体通过。

**已确认的最小关系记录：**

- A 是父实体，B 是子实体。B 的 LogicTransform 记录父实体身份 A 与相对 A 的局部位置 / 旋转；一个实体最多一个 Transform 父节点，关系限同一逻辑 World，拒绝自挂接与间接成环。
- B 的父引用是关系真值；Runtime 维护从它派生的 A 子列表，供查询 A 挂了哪些实体。子列表是可重建索引，不是第二份由玩法独立维护、同步或持久化的关系真值；不能直接把旧 World 组件对象引用带入重建后的关系。
- “B 挂着谁”读父引用，“A 挂着哪些人”读只读子列表。挂接 / 换父 / 解绑都经统一结构入口，在现有 ECS 结构结算中一致更新双向查询；未结算的请求不伪装成已经生效的关系。

**已确认的更新规则：**

1. A 的位姿控制者更新 A 的逻辑位姿，框架按父先子后的依赖得到 B 的世界位姿。B 的局部位姿不变时不需要玩法逐帧写 B；后续业务读取 B 的世界位姿必须反映已经生效的 A 更新，不能只在渲染前才算对。
2. B 若调整相对位置或朝向，由 B 当前唯一控制者改其局部位姿；“被背负时暂停普通走路、是否允许挣脱”等由背负玩法切换控制模式，不能让普通走路与挂接控制同时争写。由父关系推导世界位姿不算第二个业务写入者。
3. 首期背部逻辑挂点可以是 A 坐标系中的固定偏移；骨骼动画只影响客户端挂点 / Model 的表现偏移，不能让服务器碰撞依赖客户端动画骨骼。
4. 默认 SetParent 保世界位姿，因此“建立父子关系”不会自动把地面上的 B 放到 A 背上。上背动作需明确目标局部挂点；位移过程由玩法推进，若选择瞬间对齐则走显式跳变语义，不能暗中覆盖位置绕过 Teleport 规则。
5. 表现层先算 A 的 Model，再用 B 的局部表现位姿组合 B 的 Model；逻辑碰撞与范围判定继续使用逻辑世界位姿。

**已确认的生命周期默认值：**

| 事件 | 确认结果 | 责任边界 |
| --- | --- | --- |
| A 断线，服务器 A 仍存在 | 不自动解绑 B；A 继续参与世界模拟，失去输入不等于冻结 Transform | B05 是已有断线约定；背负是否因离线主动结束由玩法决定 |
| B 断线，服务器 B 仍存在 | 不自动解绑 B，不自动销毁 A 或 B | 同上 |
| A 真正销毁，B 仍存活 | 在移除 A 前取得 B 的有效世界位姿，统一清除 B 父引用与 A 子索引，B 保持该位姿成为无父实体 | 沿用 B01 的默认解绑；之后下落 / 安置由移动、物理与玩法处理，Transform 不负责找地面 |
| B 真正销毁，A 仍存活 | 从 A 子索引移除 B，清理 B 的绑定与表现；A 的位姿和生命不受牵连 | Runtime 清理关系，Client 清理 B 表现 |
| A、B 同一次结构结算中均销毁 | 二者各按已有结构销毁语义清理，去掉关系，不把已销毁 B 重新作为解绑活体发布 | 同次结算结果一致可见 |
| A 只是在某客户端离开 AOI | 不等于服务器 A 死亡，不由客户端改服务器父子关系；B 仍可见时使用既有父不可见兜底 | 服务器关系与客户端可见性分开 |
| 明确设置“随父销毁”的关系 | A 销毁时按显式选项销毁子实体；背负另一名玩家默认不选 | B01 已有选项，不能默认给所有父子关系套级联销毁 |

本组确认的核心是“父子关系默认只决定跟随；实体真正销毁才触发框架默认解绑，断线本身不自动拆关系”。如果玩法要断线立刻放下 B，它在正常业务相提交解绑 / 放下动作，复用现有入口；代价是玩法多一个明确条件，无需让 Transform 引入账号和网络策略。

**剩余边界：** 关系和生命周期语义已经确定；方法签名、同步 / 持久化布局、重建绑定的具体存储和时间轴继续归 Q01-Q05，不自动冻结。

#### Q04.2 子节点数量与车辆载员（已确认，问题关闭）

用户继续问：怎么查询自己有几个子物体；一辆车最多载 4 人时，怎么知道已载几人。在数量与乘员区分说明后，用户回答“好的，没问题”，确认以下查询口径与玩法边界，记入 D19。保留 Q04.2 编号供旧引用定位。

- **D16 的查询含义**：可枚举一个实体当前已生效的直接子实体，并取得其数量。`Children.Count` 只是便于讨论的接口名称示意，最终签名未冻结；这里的子实体是 ECS 挂接实体，不包含渲染模型内部的骨骼 / 节点。孙节点不计入直接子数量。
- **已确认的玩法边界**：车辆乘员数 = 直接子实体中符合该车乘员定义的数量；简单车辆约定“直接挂车的角色就是乘员”，按角色类型筛选。Transform 只管父子关系，不内置“乘员”分类，也不另存一份需要手工增减的乘员计数。
- 例子：车辆挂了 2 名角色和 1 个货箱实体，则直接子实体数为 3，按上述乘员约定得到载员数 2；容量 4 时剩余 2 个位置。只有当所有直接子实体都是乘员，才能直接用子实体数量作为人数。
- **“车上都是谁”的查询说明**：子列表可枚举具体子实体身份；按乘员条件筛选得到乘员实体 ID 列表，再通过现有类型化组件读取查询姓名等信息。人数是同一名单的数量，不另维护一份上下车人员表。服务器查询其权威世界中的关系；客户端只能查询已同步、可见的实体与字段，不能把本地未知当成服务器无人乘坐。
- 查询返回已结算生效的关系。上下车 / 销毁 / 换父经统一入口结算后，查询随关系索引更新；显示人数直接读取，不由玩法在多个回调中手动加减。
- “最多 4 人”属于上车玩法的准入规则。若后续实现上车能力，服务器统一判断容量，还须计入本 Tick 已接受但尚未结算的上车请求，避免两人同时读到最后一个空位而超载；这不是给 Transform 增加车座状态。
- 本例只回答数量查询；驾驶位 / 座位编号 / 抢座规则尚未讨论，不据此引入完整座位系统或新的 Entity。

#### Q04.3 Teleport 跳变跨同步保留（已确认，问题关闭）

用户回答“可以”，确认“传送标记随位置保留，新的传送只处理一次，直接接上最新结果”，记入 D23。保留 Q04.3 编号供旧引用定位；本次确认不冻结标记的具体字段或预测操作关联实现。

**已有依据**：D10 已确认专门 TP 入口与立即跳变；H04 记录旧稿用移动版本防止旧位置拉回。这里补齐跳变如何随状态传递，不新增实体、World 或独立事件系统。

**已确认策略**：位姿同步保留“最近一次有效跳变”的可识别标记，后续普通移动也保留它。接收方从已验证且完整提交的结果发现尚未消费的新跳变时，清旧插值 / 外推 / 纠偏历史，直接接到该次完整结果对应的新位姿，随后恢复正常移动平滑。

- 例子：角色从 A 传送到 B，又从 B 走了 0.2 米，客户端才收到合并后的状态。它仍能识别中间发生过 TP，直接显示最新结果，不能从 A 平滑穿过去，也不能先退回 B 再追赶。对本地控制实体，消费的结果仍须包含必要的权威应用与预测重放。
- 同一次跳变的重复样本不重复清历史；已经接受较新状态后，迟到的旧状态不能拉回角色。新鲜度与跳变识别分别验证，不能只靠跳变编号判断整份复制包是否可以丢弃。
- 普通更新不能将标记重置为“未传送”，否则 TP 样本被后续状态合并覆盖时会漏掉跳变。多次 TP 已合并且只剩最新有效结果时，表现无需依次展示过时落点；本节不裁决额外特效事件的投递。
- 优先复用能表达上述语义的现有身份 / revision / GAS 操作标识，证明不足才加最小字段。“传送编号”只是通俗解释，尚未冻结类型、位宽或递增位置；普通 revision 每次移动也会变化，单独使用不证明发生过 TP。
- 标记消费状态只在完整结果成功发布时前进；失败的权威应用 / 重放不能吞掉尚未显示的跳变。初次可见实体直接初始化当前位姿，不补播历史 TP。
- 本地预测 TP 与服务器确认、重放需识别同一次操作；简单回滚一个自增计数不足以证明跨预测分支去重。具体关联与预测被否决时的处理留给现有 GAS 对账合同，不在此新建另一套预测机制。

**替代与成本**：一次性 TP 通知也可成立，但同步层须保证它不会在合包或跳过表现历史时丢失，并与相应位姿保持顺序。推荐随状态保留标记，成本是最少的同步标识和接收方已消费记录，可放在现有实体状态及平滑状态中；具体字段与存档 / Hash 边界仍按 Q05 收口。

**剩余边界**：跳变随状态保留和消费行为已确认；具体字段布局、复用哪一现有标识、继承链跳变表达与 GAS 预测去重实现仍需接口和场景验证，不据本节新建事件或预测系统。

#### Q04.4 父不可见时的兜底与显示参考切换（已确认，问题关闭）

用户回答“确认”，接受“父数据可用时相对跟随，不可用时世界位姿兜底，恢复后平滑切回，关系不解绑”，记入 D24。保留 Q04.4 编号供旧引用定位；不据本次确认改写完整 AOI 规则或冻结同步字段布局。

**已有依据**：B01 已声明父不可见时发世界位姿；B06 默认父子成套进视野，模型加载与位姿数据可用分开。D18 已确认 AOI 不可见不等于服务器销毁。本节把这些声明接成最小消费规则，不重新裁决 AOI 的完整过滤体系。

**已确认策略**：正常使用父引用 + 局部位姿；当某观察者允许继续接收子实体、但不能取得有效父位姿时，服务器为该观察者提供子实体的世界位姿作为兜底。父参考恢复可用后，再切回父 Model + 局部位姿组合。

- 以 A 背 B 为例：正常先有 A 的数据，再得到 B 的跟随结果。只有 A 的模型资源尚未加载或暂不绘制时，仍用 A 的有效 Model 位姿组合 B，无需创建占位 Entity，也不因缺模型而改坐标表示。
- A 的位姿数据确实不再可用、B 仍获准可见时，以 B 的已完成逻辑结果派生世界位姿并按正常表现策略消费。兜底值不是另一份可写逻辑真值，服务器挂接关系保持不变；客户端的显示参考切换不调用逻辑解绑。
- 父驱动子世界位姿变化时，即使子局部位姿未变，兜底投影也必须更新。仅在此兜底路径承担子世界位姿的同步成本；父可用、子局部位姿不变的常态继续保持 B01 的位置零增量目标。同步调度复用现有投影，具体脏标记与编码留 Q05。
- 参考表示和所携带位姿须在同一有效提交中解释一致，不能把局部位置误读成世界位置。参考切换保住当前世界 Model，清理旧参考下失效的历史，再消除与新目标的表现误差；不将一次可见性变化自动解释为 TP。若同时有有效 TP，则按 D10 / D23 跳变。
- 兜底与父链数据未准备好时，不发布无法解释的新局部样本，保留上次有效显示并遵守 D21 的外推上限；初次没有有效位姿则等初始数据。父恢复后也须等兼容的关系 / 位姿样本，不能只因同名资源到达就切回。
- 不为取得父位姿绕过服务器的可见性裁决；数据投影、不可解析父引用及其公开范围沿用现有同步合同。世界兜底只解决位姿表达和显示，不证明本地预测碰撞已具备平台 / 支撑所需逻辑状态。

**替代与成本**：对子实体始终额外同步世界位姿可简化切换，但父一动就可能让全部子实体产生额外位置流量，偏离 B01 的常态目标。推荐只在父数据不可用时启用已有世界兜底，代价是一个明确的参考表示及切换处理；不增加 World、Entity 或独立关系真值。

**剩余边界**：兜底和切换行为已确认；具体参考表示、投影脏标记、初次数据就绪与恢复时的接口继续按 Q03 / Q05 收口，不代表已有端到端实现。

| Entity 销毁、AOI 离开、重连、旧资源迟到 | 组件生命周期跟随 Entity；资源结果由 Client 资源机制处理，Transform 不另立规则 | D27 职责已确认；作为 ECS / Client 集成依赖 |

## 兼容影响
