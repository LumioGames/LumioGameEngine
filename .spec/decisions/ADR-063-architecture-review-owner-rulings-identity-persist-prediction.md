# ADR-063：2026-09-05 架构评审 Owner 裁决——世界模型强约束、客户端三态、占段发号、帧内读写、共享字段放开、存档记账一本、预测按 GAS 原文、验收切片改为炸弹人战斗

状态：Draft（2026-09-05，Owner 就外部架构评审报告逐条裁决；随 tick.md、炸弹人需求真值与 R5-01 契约卡落地后转 Accepted）
取代：无（修订 ADR-058 第 1 / 5 / 7 / 14 / 15 条与 ADR-060 第 5 / 7 / 11 / 12 条在本轮裁决下不再成立的措辞；两份 ADR 正文不改写，各追加「修订记录（2026-09-05，ADR-063）」段。ADR-061 第 5 条 AccountWorld 维持，不重开）
Owner：`LumioGameEngine`（裁决与契约真值）、`LumioGameRuntime`（ECS / GAS / 生成器 / codec 唯一实现）、`LumioVoxelEngine`（体素）、`LumioServer` / `LumioClient` / `LumioGame`（消费方）

## 治理原则

- 沿用 ADR-056：**第一性原理——如无必要，勿增实体。**
- 沿用 ADR-058：**AI Agent 友好**——同一件事只在一处维护，每件事只有一种写法。
- 沿用 ADR-060：**彻底清理，不留兼容。**
- 本 ADR 新增三条（Owner 2026-09-05）：
  - **世界模型强约束**：世界只有体素与实体两种东西；GAS 是实体上的组件。原文在 [`rules/system.md`](../rules/system.md)「世界模型」一节，每次 Agent 初始化强制载入，本 ADR 只引用不复述。
  - **玩法归玩法、引擎归引擎**：引擎是通用底层模块，不为任何具体游戏做特殊定制；「换个游戏还成立吗」不成立的逻辑不进引擎。
  - **ROI 原则**：架构与需求讨论一律大白话并附带编号步骤的游戏例子。

## 背景

外部架构评审报告（2026-09-05，以 `ce5ed03` 为落点）对 ecs / ds / gas / save-load / voxel 五份设计概要与 ADR-058 / 060 / 061 / 062 提出 11 项问题、3 处不一致与「关键路径优先级倒置」判断。主会话逐条对照仓内原文核实后与 Owner 讨论分歧，结论：报告总体成立——9 项为真缺口，其中 4 项的修法与报告不同；1 项部分同意但牵连更深（共享文件字段）；1 项不重开（AccountWorld）。报告没看到的更深一层：四份概要把「13 相 Tick」当宿主既有契约引用 35 次，但它只活在 Historical ADR-002 / 027 / 030 与已删除的 schema 里，仓内没有活文档；报告的「帧内读视图未闭合」正是这个空洞的症状。讨论中另暴露三处引擎缺口（游戏系统不能注册进 Tick、`Sync<NetEntityId>` 不支持、tick 频率无定义）。

炸弹人切片（LumioGame ADR 0015 / 0017）已把炸弹建成实体（`BomberBombEntity`，引信到点转爆炸态 → 留火 → 销毁），与本 ADR 的世界模型一致，无需改。

## 决策（Owner 逐条裁决，2026-09-05）

1. **世界模型强约束落 `rules/system.md`。** 世界只能有体素与实体两种；静态不动没有服务器逻辑的是体素，会动、需要服务器逻辑的是实体（要同步的即 CS 实体），只有客户端表现的是 Local Entity；既不动又有逻辑的（箱子）按 voxel M6a 拆两半、一条稀疏引用相连；GAS 只能是实体上的组件，逻辑预测、客户端预表现与预测回滚一律经 GAS，GAS 可以创建实体；出现第三种东西 = 架构变更先开 ADR。待 Owner 复核一处措辞：Owner 原话「服务器回滚」，GAS 裁决流水 8b（gas.md M7 ②）定「服务器永不回退」；本 ADR 按「客户端猜错按权威拉回、服务器不回退」写，若 Owner 意指服务器侧也回退，需同时改 GAS M7。
2. **客户端三态，墓碑推导只在服务器。** 客户端对一个实体只有：有副本 / 没副本且服务器没说（未知——可能没进视野、可能还没发到）/ 收到过「已终结」的销毁记录。客户端**不得**按见过的最大号推导墓碑（AOI 上线后会把视野外的活体误判为死）。服务器墓碑推导（号已发出且不在活体，不存集合）不变。销毁记录带 `reason ∈ { left_aoi, terminated }`，客户端据此区分「走了」和「死了」。
3. **发号先占段再发；网络 ID 认人、本地句柄定位。** 发号器按块（如 1024 个）向存档预留号段，预留落盘后才从段内发号；快照存「已占到哪」而不是「下一个号」；崩溃恢复从已占段之后继续，段内没用完的号作废——没发出去的号没人持有，把它答成墓碑无害；不设发行代次。ADR-060 第 11 条 ④「NetEntityId → 实体走密集数组」由「必须」改为「参考做法」：网络 ID → 本地句柄的查找结构归实现仓（ecs M8「冻 API 不冻布局」），架构只要求内存不随历史创建量无界增长。
4. **帧内读写规则写进 `knowledge/features/tick.md`，不重新定义提交点。** 前两层已清楚（改字段当场生效、生删延迟到 `EcsCommandBufferCommit`），补第三层地形：业务相读地形只读帧初；同一 tick 内多个业务批次在 `VoxelCommit` 前合成一批、一次提交，`expectedSectionRevision` 只校帧初 revision；帧内不提供「读到本帧已下单改动」的读法，连锁这类「本帧已改了哪些格」由玩法在自己的帧内工作集里算（炸弹人：帧初读一次整图到本地数组，本帧全在数组上算，连锁同帧用队列算完，帧末一次提交；去重靠批次本身，击杀去重靠血量当场生效）。`tick.md` 同时承载 13 相表（相名 / 可写域 / 对后续相可见性 / 失败类 / 提交点）、`VoxelCommit → EcsCommandBufferCommit` 次序、游戏系统注册方式与 tick 频率归属；四份概要的「宿主地盘」改为链接它。
5. **共享文件允许不上网的普通字段。** ADR-058 第 5 条「共享文件只许 Sync 字段」放开：两端都要算、都不上网的工作状态（移动技能的转角缓冲）放共享文件一处维护；lint 改查「共享文件里声明的普通字段若只在 `.Server.cs` 或只在 `.Client.cs` 里被赋值」即报错（那是放错了位置——另一端会多一个永远是默认值的死字段）。理由：原规矩把逻辑预测的路堵死——预测代码必须在共享文件，其工作状态却无处放，逃生口只有「同一字段写两处」或「白发流量」，两者都撞既有原则。
6. **存档记账只有一本：要存档的字段一律 `Sync<T>`。** `[Persist]` 只能打在 `Sync<T>` / `SyncList` / `SyncDict` 上，打在普通字段上生成报错；要存档但不上网的字段写 `Scope.None`（不发给任何人，只为记账）。复制按 `Scope` 挑人，存档不看 `Scope` 全收；ecs M4③「没人看不记账」改为「没人看不打包」，账照记。修 ADR-058 第 1 条（未标注字段 / `[Persist]` 措辞）、第 7 条（`Sync<T>` 与 `[Persist]` 的关系）、第 14 条「`[Persist] AccountId`（Server.cs 普通字段）」与第 15 条「私有字段…存档打 `[Persist]`」的措辞。样板 `LastMessageText` / `LastMessageTick` / `AccountId` 改 `Sync<…>(Scope.None)`。
7. **预测按 GAS 裁决流水 8a / 8b 原文（[`reviews/2026-08-30-gas-architecture-decisions.md`](../reviews/2026-08-30-gas-architecture-decisions.md)，即 gas.md M7 ①②），只补一个包级字段。** 客户端有「确认世界」与「预测世界」；每包权威状态到达，预测世界从确认世界整体重建并重放未确认输入；通过 / 没通过不是一次判断，是重建的自然结果（通过时重建出的预测世界里站着的就是正式实体，画面不变；没通过时它随重建消失）。**不给创建记录盖预测键 / 认领键、不做改号、不做「假实体换真实体」**；表现层按稳定键（`fx_key` + 参数）保持连续。**预测世界只含被预测的域，退多少由预测了多少决定**：第一版 = ECS 实体（位置在内），体素不进预测世界、不拍快照。唯一新增：C-1″ `WorldChange` 包级 `appliedInputSequence`（本观察者已处理到第几号输入）。移动是 GAS Ability（玩家按方向键 = 放移动技能，写 `LogicTransform`）；服务器只有 `LogicTransform`，客户端另有只做插帧的 `ModelTransform`。ecs M10 ①② 并到此口径。
8. **可见性本身变化也是同步事件。** `Claim` / `Owner` 名单新加一个观察者 = 向他补发该字段当前值（走 PostAttribute 语义）；移除 = 向他发字段失效记录，客户端把该字段置「不可见」。持久名单存 `AccountId` 不存 `NetEntityId`（超时重登会换实体号）。修 ADR-060 第 5 / 12 条。
9. **删「整块内存拷贝」硬要求，组件保持 class。** 模板批量创建 = 池化 + 生成的按类型克隆（`Sync<T>` 内含所属组件引用，拷完必须指向新实体自己的组件，不是一次内存拷贝）；做完标准改为三个数：每千实体创建耗时、每实体堆分配字节（池热后为零）、GC 次数（为零）。修 ADR-060 第 11 条 ①。
10. **网格不倒退、允许受控落后。** voxel M4 纪律 2 改：只允许上传比已显示版本更新的网格（revision 单调）；生成期间 Section 又被改了照常上传并追赶最新 revision，不作废；滞后有预算（数值归实现仓）；句柄有效性只由释放契约决定。降 P2。
11. **每连接允许有界元数据；阶梯前三级仍看 revision 深度。** ds M6「每连接只有一个书签」改为「不存组件值副本，允许有界的可见性 / 发送进度 / 确认元数据」（ecs 视野表本身就是 per-viewer）；慢客户端阶梯 1–3 级信号保留 revision 落后深度（单一仪表、双端可算），第 4 级硬上限明确按待发字节；「关键类别最多欠 N 帧必发」加「本帧配额允许」前提，配额装不下即进第 3 / 4 级。
12. **三处不一致修正。** ds M9「Room 多槽」改「V1 一进程一房间，多槽为回图触发项」；ecs §2「不存在整图加载」删除，地图加载与整图常驻归体素声明；样板补 `ObserverComponent` 与 `IdentityComponent` 只剩 `Name` + `AccountId` 归 R5-01（ADR-060 已列）。
13. **引擎验收切片改为炸弹人战斗；不接受「暂停并行扩展框架」。** 聊天切片验不出帧内结算、身份、预测三组根问题；写 `knowledge/features/bomber-slice.md` 作需求真值（能力组合 = 移动 / 放弹 / 连锁爆炸 / 破坏方块 / 伤害 / 死亡 / 掉落 / 重新入场 / 网络一致；五组验收场景）与第二样板。派活口径：体素 15 卡照 `plans/2026-09-05-voxel-impl-dispatcher-prompt.md` 并行派；RM-00011 R5 只收口不扩；GAS / 存档 / 休眠 / AOI 分帧卡不派。「暂停并行扩展」与「快 > 稳 > 好」冲突，不采纳。
14. **引擎缺口登记（派卡，不在本 ADR 内实现）。** ① 游戏系统不能注册进 Tick（LumioGame ADR 0015：Runtime 无公开 `ISystem` / `IProcessor`，`WorldManager.Tick()` 内部序列固定）——`tick.md` 定注册方式，派 Runtime 卡；② `Sync<NetEntityId>` 不支持（LumioGame 以裸 u64 绕）——ecs M4② 把 `NetEntityId` 列为一等标量，派 Runtime 卡；③ tick 频率无定义——归游戏配置，落 `WorldEntity` 的 Tick 配置字段，`tick.md` 写明，GAS「秒换帧」引用它；④ C-1 缺输入确认链——第 7 条的 `appliedInputSequence`；⑤ ADR「兼容影响」无机器校验——spec-lint 增校验：Draft ADR 兼容影响点名的知识文档必须含该 ADR 编号。
15. **不采纳。** AccountWorld 重开（ADR-061 第 5 条维持，只在平台 ADR 补失败语义）；创建记录盖认领键 / 预测键；体素「本帧工作副本」读法；发行代次；`Persist<T>` 第二种包装；炸弹做成「列表记录不是实体」。

## 替代方案

- **客户端两态（有 / 没有），「死了」只由服务器答**（主会话提案）：Owner 否——按报告三态，客户端记收到过的销毁记录，需要销毁记录带原因。
- **发行代次（号码加「第几次启动」段）**（报告）：被否——占段 + 高水位已解决，代次多一段号、多一条墓碑规则。
- **只改布局、崩溃重号等存档切片再定**：被否——占段一次写清。
- **体素提供「本帧工作副本」读法**（报告）：被否——多一条读路径和一份帧内副本；玩法规则由玩法定，玩法自己在帧初快照上算。
- **连锁隔一帧再爆**：被否——每跳慢一个 tick，手感变。
- **爆炸传播下沉 Rust**：被否——把炸弹人规则塞进引擎，违反「引擎归引擎」。
- **共享文件放开但不要 lint / 维持 9-03 裁决**：被否——折中 lint 仍能抓死字段；维持原裁决则预测的中间量要写两处。
- **`Persist<T>` 第二种包装 / 普通 `[Persist]` 字段只进快照不进流水**：被否——第二种包装让不上网的存档字段看起来「会上网」；后者同一组件两种耐久保证。
- **创建记录盖「输入序号 + 动作序号」**（报告）/ **盖「施法者 + 声称帧」**（主会话一度提案）：被否——GAS 裁决流水 8a「不发小票」（gas.md M7 ①）已覆盖，预测世界重建后不需要对号；多一层只在不重建的局部优化时有用。
- **整帧倒带含体素，现在就做**（GAS M7 原措辞）：被否——只预测移动时结果与只退字段相同，却要每帧拷 64 KB 地形；改为「预测世界只含被预测的域」。
- **炸弹做成地图上同步列表的一条记录（不是实体）**（主会话一度提案）：Owner 否——一切皆实体，要同步就是 CS 实体。
- **AccountWorld 不作架构强制项**（报告）：不重开——Owner 9-04 已裁，写入只经一条路径。
- **阶梯信号加字节 / 最老消息年龄 / 确认落后**（报告）：部分采纳——只在第 4 级硬上限按字节；前三级单一仪表的理由成立。
- **暂停并行扩展框架、先用炸弹人验证**（报告）：半采纳——验收切片改为战斗；不暂停并行。

## 接口 / Schema

- **C-1″ `engine/wire/gameplay-command-envelope-v1.json`**（形状由 ADR-060 定、R5-01 卡填实；本 ADR 追加两处，随 R5-01 一并落）：`WorldChange.destroys[].reason ∈ { "left_aoi", "terminated" }`（必填）；`WorldChange.appliedInputSequence`（u64，本观察者已处理到的输入序号，0 = 尚无）。当前 main 上的 C-1 仍是 `FullSnapshot` / `Delta` 旧形态，不在旧形态上加字段。
- **`Scope` 枚举增 `None`**：不发给任何人、只为存档记账；`Sync<T>(Scope.None)` 与其他 Scope 同一写法、同一脏账。
- **`[Persist]` 约束**：只能打在 `Sync<T>` / `SyncList` / `SyncDict` 上；生成器对普通字段上的 `[Persist]` 报错。
- **类型阶梯**：`NetEntityId` 为一等标量，`Sync<NetEntityId>` 合法（Runtime 卡落地）。
- **发号器快照字段**：存「已占到哪」（reserved-through）而非「下一个号」；快照格式由 Runtime 卡与存档契约卡填实。
- **共享文件 lint**：共享文件允许普通字段；规则 = 共享文件声明的普通字段若只在 `.Server.cs` 或只在 `.Client.cs` 被赋值 → 错误。
- **`tick.md`** 为 13 相表、可写域、帧内读写规则、游戏系统注册方式、tick 频率归属的活文档真值；相名以 Runtime `modules/simulation` 的 `TickPhase` 枚举为准。

## 失败语义

- 生成器：普通字段打 `[Persist]` → 生成失败；共享文件普通字段只在一端被赋值 → lint 失败。
- 客户端对未收到过 `terminated` 销毁记录的号答「墓碑 / 死了」——结构断言失败，收口审查退回。
- 创建记录出现预测键 / 认领键字段；客户端出现「假实体换真实体」搬特效代码——收口审查退回。
- 体素提供帧内工作副本读法；引擎出现只对某一款游戏成立的原语（如「爆炸传播」）——收口审查退回。
- 快照存「下一个号」而非「已占到哪」、或发号前未落盘预留——存档验收失败。
- 网格交付因「Section 在上传前又被改」而丢弃已完成网格——体素验收失败。
