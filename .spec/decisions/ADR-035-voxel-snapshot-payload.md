# ADR-035: Voxel Snapshot/Diff Payload and Canonical Capture Semantics

- **Status**: Accepted (accepted 2026-08-27 additive to `LGE-V1.3-2026-08-27`; formally entered Implementation Baseline `LGE-V1.4-2026-08-27`)
- **Owner**: `LumioVoxelEngine` (payload producer/consumer), `LumioGameRuntime` (SnapshotCut coordinator), Architecture (registry)
- **Baseline**: `LGE-V1.3-2026-08-27` line
- **Relation**: Consumes the voxel types frozen by [ADR-024](ADR-024-voxel-p0-contract-set.md) (`voxelChunkId`, `voxelContext`, `voxel-revision-stamp`, page envelope). The payload defined here is carried by the `snapshot-header` envelope of [ADR-010](ADR-010-persistence-config.md) and captures the SnapshotCut consistency of [ADR-003](ADR-003-cross-world-txn.md); it supersedes none of them. The write-side durability handshake for the same pages is [ADR-036](ADR-036-voxel-streaming-durability-ack.md).

## Context

The architecture source froze the generic `SnapshotHeader` envelope, but no public contract existed for the voxel bytes inside it: chunk ordering, page indexing, partial (AOI-subset) snapshots and incremental (base-to-target) diffs were undefined, and the voxel repository documented mutually contradictory snapshot concurrency stories (stop-the-world encode vs. never-pause encode — voxel review VXL-009, contract gap §6). Without a frozen payload contract and a single capture model, implementations could produce non-reproducible snapshot bytes, emit `Ready` after their pinned view was already lost, or silently rebase diffs.

## Decision

- **Cut ownership and the short barrier.** The Runtime coordinator is the only owner of the cross-world `SnapshotCut` and of the `SessionRevisionVector` it fixes. The voxel domain never creates, advances or rewrites a cut; inside one short coordinated barrier it validates the received immutable cut, establishes a Pin or copy-on-write view over the covered pages, and returns to normal authoritative writing. Encoding then runs asynchronously against that immutable capture view; quiesce-style maintenance snapshots stop ingress first but reuse the same cut-to-capture path. Stopping writes for the whole encode duration is not a conforming implementation.
- **The payload is not the envelope.** `snapshot-header` remains the generic envelope owning magic, header schema version, activation state, encryption, timestamps and the hash over payload bytes. `voxel-snapshot-payload.schema.json` describes the voxel-domain payload inside that envelope and never replaces it. The envelope's `revisions.voxelWorldRevision` and `revisions.chunkRevisionSet` must equal the payload's `cutProjection` fields; a header/payload revision disagreement is a verification failure.
- **Cut projection.** Every capture record and payload manifest carries `cutProjection`, the projection of the coordinator's cut onto the voxel domain, in exactly the `voxel-revision-stamp` shape frozen by ADR-024 (with `schemaEpoch` mandatory here). The projection enumerates precisely the chunk set the record covers: the full resident set for a full snapshot, the declared subset for a partial snapshot, the changed set for a diff.
- **Canonical bytes.** One cut yields byte-identical payloads, on every conforming encoder, every time (`determinism` = `SameCutSameBytes`). The manifest therefore contains no wall-clock timestamps and no optional fields in payload kinds (every field of `SnapshotPayload`/`DiffPayload` is required; `removedChunkIds` is present even when empty); chunk tables are arrays, never key-ordered maps; entries are sorted in the single canonical order `chunkOrder` = `CoordXYZAscending` (ascending signed x, then y, then z); per-entry `byteOffset`/`byteLength` are contiguous and ascending and sum to `payloadLength`; `payloadHash` is the SHA-256 digest of the canonical bytes. Two encodes of the same cut that differ in bytes are a fatal contract violation, not a tolerable variance.
- **Page index and partial restore.** Each chunk entry carries its `chunkRevision`, its hashed page table (the ADR-024 page envelope: `pageIndex`, `pageVersion`, encoding, length, SHA-256, compression) and its byte range inside the payload, so a consumer can restore a chunk subset without decoding the whole payload.
- **Partial snapshots.** `scope` = `Partial` declares an explicit AOI-subset payload with at least one chunk. Restore of a partial payload materializes exactly the covered chunks; a chunk absent from a partial payload is *not covered* — it must never be materialized as empty blocks or treated as deleted (the ADR-024 rule that a missing chunk is never an empty world extends to snapshots).
- **Diff payloads.** A diff references its base artifact by `base.baseSnapshotId` plus `base.baseWorldRevision` and encodes the target as a strictly positive `worldRevisionAdvance`: the target world revision is `baseWorldRevision + worldRevisionAdvance` and must equal `cutProjection.worldRevision`; canonical encoders must refuse to emit records where they disagree. A non-positive `worldRevisionAdvance` is structurally unrepresentable on the wire. A cut that does not equal `baseWorldRevision + worldRevisionAdvance` (including an inverted pair of absolute revisions) is rejected by the encoder and by semantic validation, not by JSON Schema. Applying a diff whose base identity or base revision does not match the restored state fails with `SnapshotBaseMismatch` (1039); the only degrade path is an explicit full snapshot, never a silent rebase. `removedChunkIds` lists chunks present in the base but absent at the target, in canonical order.
- **Capture lifecycle and the pin fence.** A capture advances `Requested -> Cutting -> Pinned -> Encoding -> Verified -> Ready -> Released`, exiting to `Cancelled` or `Failed`. `Verified`/`Ready` require the pin to still be held (`pinState` = `Pinned`) and the verified `payloadLength`/`payloadHash` to be present; an expired or invalidated pin can only lead to `Cancelled`/`Failed`, never to `Ready`. Pin budget exhaustion fails the capture with `BudgetExceeded` (1035) and a reclaimed cut revision with `TargetRevisionUnavailable` (1034); a failed or cancelled capture releases its pin and buffers and leaves the previous Active snapshot untouched. Encoding failure alone never faults the world; only internal view corruption does.

## Contract

`schemas/voxel-snapshot-payload.schema.json` (`kind` = `CaptureStatus` | `SnapshotPayload` | `DiffPayload`), registered in `schemas/index.json` as P1 `VoxelEngine`; the new ErrorCode `SnapshotBaseMismatch` (1039) in `ids/index.json`. Pin/COW record ownership stays inside the voxel revision infrastructure and the capture reference stays voxel-internal; only these records cross repositories. Singleplayer and Dedicated Server use this same canonical payload; they may differ only in the durability policy of [ADR-036](ADR-036-voxel-streaming-durability-ack.md).

## Failure semantics

A payload whose hash or length does not verify is rejected and never partially materialized or zero-filled. A capture claiming `Ready` without a held pin, a payload kind carrying capture-only fields, a diff without `base`/`worldRevisionAdvance`/`removedChunkIds`, and a partial payload with an empty chunk table are all malformed. A diff applied to a mismatched base returns `SnapshotBaseMismatch` and leaves the restored state unchanged. Same-cut encoders that disagree byte-for-byte, or a restore that materializes chunks a partial payload does not cover, are fatal contract violations.

## Alternatives

Extending `snapshot-header` with voxel fields was rejected: the envelope is generic, GameRuntime-owned and shared by non-voxel payloads. A chunk map keyed by ChunkId was rejected because JSON object ordering is not canonical; ordered arrays keep byte determinism checkable. Carrying an absolute `targetWorldRevision` beside the base revision was rejected: two absolute fields cannot be forced monotonic structurally, while the strictly-positive advance witness makes a non-advancing range unrepresentable and keeps that class of violation machine-checkable. Absolute inversion (`cutProjection.worldRevision < baseWorldRevision`) remains an encoder/semantic rejection. Freezing diff granularity, pin-vs-COW strategy or page-size numerics was rejected — those stay open in `DECISIONS_PENDING.md` D-013/D-014; this ADR freezes wire envelopes and ordering only.

## Compatibility and migration

Additive to the `LGE-V1.3-2026-08-27` line; no existing schema field changes meaning and no deployed voxel snapshot consumer exists yet, so no migration window is required. Changing the canonical order, the determinism rule, a state/enum value, the base-reference encoding or the payload field set later requires a new ADR, new fixtures, a `payloadFormatVersion` bump and a new BaselineId.

## Verification

Fixtures `voxelsnap/capture-ready-pinned` (held pin with verified bytes), `voxelsnap/full-cut-projection` (chunk table coherent with the cut projection, canonical order and determinism declared), `voxelsnap/partial-aoi-subset` (AOI subset), `voxelsnap/diff-base-target-round-trip` (full@24 plus diff 24->26 reaching the target stamp), `voxelsnap/capture-pin-expired-ready` (expired pin must not claim Ready), `voxelsnap/payload-bad-hash` (payload hash must be a SHA-256 digest), `voxelsnap/diff-no-advance` (a diff must strictly advance from its base). Implementations must additionally assert byte-identical re-encodes of one cut and hash-verified round-trips of full, partial and diff payloads.
