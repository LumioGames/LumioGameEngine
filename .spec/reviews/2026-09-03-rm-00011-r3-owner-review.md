## 结论

**退回。** P0 = 0，P1 = 9。

一句话：契约（C-1′/C-2′/C-4′）、声明表生成器、NativeCore 单核双模式、Arch 根表定时槽、Runtime 持久化管线、Game 退役 `ChatRoomWorld`——这一半是真落地且本机可复跑。但 ADR-056 的核心诉求「单一 ECS 与单一查询真的连在一起」「客户端真收到且两轮一致」「到期由内核触发」「跨进程读回逐实体相等」「宿主无第二份绑定表」「顶号后不自动重连」——这一半要么靠放宽 oracle 通过，要么靠 Server 仓测试代码冒充 Client 进程通过，要么只在 harness 手工推进时成立，要么查询答的是 seed 常量。live 证据包不在任何仓，Rust 侧严格验收从未运行。N-13 把六项 Fixture 全标 pass，其中三项它自己承认字面条件不满足。**ADR-056 → Accepted 的前提不成立，应回退 Draft；Server 0008「冻结条件已满足」随之不成立。**

### P1

**P1-1 两轮一致性 oracle 被放宽以使 live10 通过；Rust 侧严格 oracle 从未运行**
- Game `78d3f2b`（PR #10 内）把 `compareRuns` 从逐位 `JSON.stringify(eventOrder)` 相等改为排序多重集 `packCompareTexts(...).sort()`（`verify-evidence.mjs:666-689`），`applied-tick-compare` 只比 `length !== 101`。提交信息自述「not Bot.Host sender order」。
- N-13 报告承认「gitignore 包级 `verify-report.json` 仍是 restamp 前的 `ok:false`」——launcher 原判 FAIL，改尺后 `--dir` 复判 PASS。
- Server `tests/entity_chat_acceptance.rs:353-354` 仍严格；该测试在 CI 因 `LUMIO_GAME_ROOT` 未设 0.00 s 即 FAIL（`continue-on-error`），本机（非 Windows）无法编译；终报无其输出。Server 另有死 oracle `tests/verify_rust_evidence.mjs:325-326,354`（要求 `appliedTicks` 全 1、严格 JSON），与 suite 64 条/tick 分批矛盾，无人调用。三把尺子三个口径。
- 技术根因：Runtime `roomSequence`/`messageId` 按 capture FIFO 到达序分配，tick 内无确定键排序（`ChatIngressCapture.cs:59,71-72`；`ChatCommandRuntime.cs:177-183,420-429`）；两跑确定性测试 `ChatCommandRuntimeTests.cs:384-399` 只在单线程串行投喂下成立。100 个独立 socket 分批发送时顺序天然不可复现。
- 违反：ADR-056 Fixture 3「两轮一致」；dispatcher 提示词「不得替 Owner 补产品决定」「不把 not-ok 编码成 SUCCESS」。

**P1-2 live10 证据包不在任何仓；oracle 钉死值随行尾变化**
- Game `integration/entity-chat/.gitignore` 含 `evidence/`；origin/main 六仓无 `evidence.json` / `timer-trace.json` / `persist-snapshot.bin`。昨日深审 §4 已列「派工机证据包不在任何仓」，r3 未纠正。终报「four rounds window 101, S6 [5,10,15], S7 58340, S8 superseded true」全部不可复核。
- 钉死值 `d05f0458…` 是 **CRLF** 字节的 sha256（origin/main LF 字节为 `f2cd6779…`；`sed 's/$/\r/' | shasum -a 256` 得 `d05f0458…`）。`oracleSha256()`（`verify-evidence.mjs:30-32`）直接哈希本地文件字节，随 autocrlf 变化；同一 origin/main 在 Mac/Linux 上验不过 `oracle:sha256`。

**P1-3 N-11「Bot 节奏由 Client Timer Manager 触发」由 Server 仓测试钩子冒充 Client 进程实现**
- Client 生产：`FoundationHostCommand.cs:108` 4 参构造 → `HeadlessBotHost.cs:27-30` `timer = null`；`RunAsync` timer 分支（:70-73,:81-98）生产永不执行。`INativeTimerAbi` 唯一实现 `modules/bot/tests/Support/C4TickFrameAbi.cs`（托管假件）。
- Server `modules/process/src/entity_chat/bot_startup_hook/StartupHook.cs`（449 行 C#，`bots.rs:368-392` 运行时生成 csproj 编译，`bots.rs:204-206` 经 `DOTNET_STARTUP_HOOKS` 注入）：`Initialize()` 读 `LUMIO_BOT_FLEET_SPEC` → 自建 100 个 `ClientWebSocket` → `new NativeTickFrameAbi(spec.EngineNative)`（`LoadLibraryW/GetProcAddress lumio_engine_get_api_v1`，硬编码槽偏移 88…192，Windows-only，绕过 `Lumio.Engine.NativeLoader`）→ **一次** `timer.Advance(15)` → 按 `dues.Count` 分三批发预编码 envelope + `Thread.Sleep(400)` → 写 `timer-trace.json`（`tickSource = invoked ? "native-kernel/tickFrame" : ""`，:74-75）→ `Environment.Exit`，Bot.Host 自己的 Main 永不执行。
- 结果：`process=Lumio.Client.Bot.Host` 是进程名，行为是 Server 仓代码；「每 N Tick 触发一次提交一条 chat.input」变成「一次 Advance(15) 后 33/33/34 分批 + 400 ms sleep」。Client 卡 N-11 验收 3、4 实际由 N-10 越界完成（N-10 拥有范围不含 Client 行为）。触碰硬禁令「不得假冒进程名或宿主身份」边界；新增第二份 ABI 装载器。
- 时间线：Client #15 `09-02 14:27` 合入（自称「Bot cadence 5,10,15 via Client Timer Manager」，依据 `bot 9/9` 单测），Server r5 #27 `21:25` 才「spawn Client Bot.Host; S6 ticks from ClientTimerManager」。

**P1-4 Server 宿主保有第二份按账号索引的会话/绑定表并自行裁决顶号与跨房（ADR-056 §2）**
- `host.rs:133-143` `Session` 复制完整五元组；`:154` `account_sessions: HashMap<String,String>`；`:458-459` 顶号裁决在宿主；`:496-499` 跨房裁决在宿主；`list_admits`（`:793-809`）、`admit_chat_input`（`:619-620`）从宿主副本回答。Runtime 已有同一真值与裁决：`EntityBindingQuery.cs:28 _liveConnectionByAccount`、`:190-197`、`:741-748`。
- 分叉场景：`takeover()`（`host.rs:512-518`）先清宿主表再 `commit_session`，`attach_member` 失败（`:533-539`）即 reject，此时 Runtime 已绑定新连接而宿主两表皆空，下一次同账号 admit 得 `invalid_binding_shape`（`EntityBindingQuery.cs:745`）→ 该账号永久卡死。
- 架构测试 `tests/entity_chat_architecture.rs:85-92` 只匹配旧字符串名，`account_sessions` 因名字不同而通过——ADR-056 失败语义「宿主若保有第二份绑定表……架构测试直接失败」未落地。
- 缓解事实：Runtime `Admit` 对「账号已在线」与形状错误同返 `invalid_binding_shape`（`:743-747`），宿主拿不到区分信息才自建索引——这是 C-2′/Runtime 契约缺口，应按提示词升级为契约缺陷，而非在宿主补表。

**P1-5 五分钟到期在生产路径无驱动；S7 跨进程只证明 restore 状态码；多处证据字段常量**
