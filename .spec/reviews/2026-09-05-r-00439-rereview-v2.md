# R-00439 Corrected Deep Review

## Findings

### P1 - Root field order is not validated and the generated root is hard-coded

`eng/generate-abi.mjs:44-48` only checks required names through a `Set`; it does
not check root count, uniqueness, or document order. The C root body is then
hard-coded at `eng/generate-abi.mjs:165-199` instead of being emitted from
`root.fields`. A temporary swap of `abiVersion`-preserving root fields
`ping`/`create_clr_host` was accepted (`exit=0`), while the generated header
continued to use the old order. A root-order edit can therefore change the
ABI definition hash while bindings retain a different slot order, which can
dispatch the wrong function through a public table. Add exact prefix/order and
slot-signature validation, and generate the root from that validated model.

### P1 - The canonical cell-offset formula is not guarded

`eng/generate-abi.mjs:75-79` validates only the three stride integers. It does
not validate `formula`, `min`/`max`, `inverse`, or their agreement with the
wire contract (`engine/abi/native-abi.json:176-185`). A temporary mutation of
the formula to an x-first expression was accepted (`exit=0`), and the focused
tests at `eng/generate-abi.test.mjs:83-103` do not assert the formula either.
The checked-in expression is currently correct, but this guard gap permits
provider and consumer to derive different cell addresses, causing silent
wrong-cell reads/writes. Validate the complete frozen expression/range/inverse
or derive these values from one structured representation.

### P2 - Post-generation string replacements can silently no-op

`eng/generate-abi.mjs:231-260` rewrites the header with chained
`String.replace` calls but never asserts that each target matched. A temporary
mutation of the presence replacement target left the generated header with
`typedef enum lumio_voxel_presence_t` and no fixed-width typedef while the
generator still exited `0`. This can reintroduce implementation-defined enum
width or stale function signatures when the template changes; each replacement
must assert a match, or the header should be emitted correctly in one pass.

### P2 - Unknown field types silently become `u32`/`uint32_t`

The binding maps default to `u32`/`uint`/`uint32_t` at
`eng/generate-abi.mjs:117`, `136`, and `219` instead of rejecting an unknown
ABI type. A temporary `world_coordinate.y` type of `bogus` was accepted
(`exit=0`) and emitted as `u32` in Rust and `uint32_t` in C. A new or mistyped
public field can therefore compile with a layout different from the source
contract. Replace fallback mappings with an explicit error for unsupported
types and test the negative path.

## Verdict

**RETURN**. The current frozen values and generated files satisfy the stated
contract, but the P1 generator guard gaps are public-ABI correctness risks and
must be addressed before accepting the change.
