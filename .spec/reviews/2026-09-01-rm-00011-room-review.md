## 0. 结论

**有条件通过。** 需求室的卡片结构、身份链设计（AccountId / NetEntityId / LocalEntityId / ConnectionGeneration 分层）与非目标边界质量高，全部保留；但按创建时的原状**不可开工**。开工条件三件事：

1. 补 **Wave 0 契约冻结卡**（4 张，§5）——先冻协议再并行，落实 Owner 的 MVP 效率原则（**先定协议/API/约束 → 各仓并行互不阻塞 → 最后联调**，此原则写进每张卡作为核心提示词）；
2. 按 §6 逐卡变更清单修订 11 张卡（宿主轨道、账号服归属、顶号语义、Timer 消费者、验收修正）；
3. 全部卡挂入 MS-00001。

审查中发现的框架级悬空问题已与 Owner 逐题裁决（§3），均不再是阻塞项。

## 2. 审查维度结论（对应任务书 A–E）

- **A 总目标**：目标清晰、可交付、可验证（101 Entity 主场景具体且可计数）；确是 Hello World 之后合理的第一条正式 ECS 纵切。存在两处范围压载（Timer 无室内消费者、持久化验收静默扩权到整房重启恢复），经裁决分别以「补真实消费者」与「收窄到组件级」化解。隐含目标冲突一处：切片必须解 D-009，而立项决议「维持阻塞」——已由 Owner 明示解冻。
- **B 卡正确性**：无重复卡、无环依赖；标题/背景/目标/验收/边界总体一致。主要问题是三个「悬空」：契约冻结无生产者卡、宿主轨道双边下注、账号服目标仓虚指（§4 P0 项）。Bot 命名空间在需求层双侧闭环（账号侧注册/认领受限 + 游戏侧准入需 Bot 工具上下文），不存在仅靠用户名伪造 BotEntity 的通路；但「Bot 工具上下文」本身尚未冻结成真凭证契约，且验收漏测「普通客户端登录已存在 Bot 账号」路径。
- **C 验收质量**：39 条大多客观可执行。需修正的：R-00346「拒绝或幂等返回」二选一（已裁决顶号）；R-00345 把未建立的 DAG 当交付；R-00354「或显式 blocked 前置」逃生门使「完成」语义含糊；少量不可测形容词（clean / equivalent / fail safely / observable and safe）需替换为契约口径。需新增 2 条（§6 R-00344）。无「接口已定义=功能完成」类项。
- **D 依赖与排期**：室内 DAG 无环；原 Wave 0–5 内部自洽，但外部整体被未冻结契约与 ECS 地基卡（他室 backlog）门控——真实 Wave 1 应是契约冻结（原计划缺失该层）。按效率原则重排为「Wave 0 契约 → 各仓管线并行（同仓串行/异仓并行）→ 联调」（§5）。错误方向边一条：R-00350→R-PERSISTENCE（重连重建用的是复制 FullSnapshot，非持久化 Snapshot/Restore，两个「快照」须显式区分）。
- **E 风险与非目标**：五分钟保留、进程重启不保窗、tombstone/永不复用、跨 Room 隔离均已明确；Chat 未错误承担历史/审核/离线/持久化职责。本阶段必须补的仅两项：ChatInput **文本长度上限**与**每发送者速率/每 Tick 提交策略**（丢弃或拒绝）——随 C-1 契约卡一并冻结，不另立卡。高风险未冻结面（Account Port、Entity Query、Chat mapping、Timer ABI、Room snapshot key）已全部转为决策门并经 Owner 裁决或指派冻结卡；Room snapshot key 随持久化收窄移出本室范围。

## 5. 修订后的目标句、分组与 Wave 顺序

**目标句**：

> 在冻结的宿主无关公共契约之上，于 C# MVP 宿主交付 Hello World 后第一条正式 ECS 纵切：100 个 Bot 账号与 1 个浏览器账号经独立账号服务 login-or-register 取得凭证并进入同一房间，生成 100 BotEntity + 1 PlayerEntity 共 101 个 Game ECS Entity；聊天文本经通用玩法命令信封上行，在固定 Tick 提交 `ChatComponent.SetMessage` 并向全房间可靠有序广播；含五分钟断线保留、顶号/重连重绑、过期销毁与组件级快照往返；随后由切片级最小 Rust 宿主复跑同套验收并使 C# 宿主退役。聊天历史、整房重启恢复与生产安全策略显式除外。

**分组与 Wave**（效率原则：Wave 0 全并行冻契约；实施期跨仓并行、同仓串行；联调收尾）：

- **Wave 0 · 契约冻结（架构仓，4 张新卡全并行；每张按 ADR→Schema/ID→Fixture→Baseline→七仓镜像交付）**
  - C-1 通用玩法命令信封与聊天映射：ADR-049 定稿 + D-009 解阻；ChatInput/ChatMessageEvent/ChatComponent 映射；文本长度上限与速率/每 Tick 提交策略；挖方块纸面套验。
  - C-2 连接绑定与 NetEntityId Attribute Query 契约：绑定五元组、自查、可见性/权限/revision/stale/tombstone 失败语义。
  - C-3 Account Auth/Profile Port 与准入契约：login-or-register、凭证签发/校验、Bot 工具真凭证 claim 与失败码、顶号语义、第三服务拓扑 ADR。
  - C-4 Timer ABI：TimerHandle/CallbackSlot、双层定时分层（宿主闹钟 vs Native 节拍器）与终态统一方向、生命周期 Fixture。
- **并行前置主线（他室，需立即排期，为本室最长杆）**：GameRuntime ECS 地基 R-00149→R-00150→R-00152→R-00172（→R-00178→R-00189）。
- **Wave 1 · 实施（契约冻结后各仓管线并行）**
  - LumioServer 线：R-00344（account-server）→ R-00346（准入+顶号）→ R-00350（重连/过期）
  - LumioGameRuntime 线：R-00347（绑定/查询）→ R-00351（聊天映射实现）→ R-00353（组件级快照）
  - LumioGame 线：R-00348（ChatComponent）
  - LumioClient 线：R-00349（ReplicaWorld/呈现）
  - LumioNativeCore 线：R-00352（Timer Manager + 消费者接线）
- **Wave 2 · 联调与接力**：R-00354（101 实体 E2E）→ C-5「最小 Rust 宿主复跑」（新卡，接力条款落地，通过后 C# 宿主退役）。

原 Wave 0–5 编排在室内自洽，其真正缺陷是缺 Wave 0 契约层——本方案保留原有先后关系，将其折叠进「同仓串行」的管线内。
