## Boundary Rules

1. The architecture repository owns ADR -> Schema/ID -> positive/negative Fixture -> README/Baseline -> consumer mirror order. Downstream repositories consume generated or mirrored artifacts and never redefine them.
2. Runtime GAS files stay under modules/gas/** with corresponding tests. Runtime work never edits user-owned ECS or global.json changes.
3. NativeCore uses independent stateless crates and a stable scalar/slice/bounded-result ABI. It does not expose gameplay classes, ECS authority, or a second state store.
4. Game declares content, config, mapping, and scenario only. Game does not copy Runtime lifecycle logic or ECS authority and reaches Voxel only through IVoxelWorldPort/CrossWorldTxnV1.
5. No FxComponent, RPC/sync layer, Task, PredictionWindow, wall-clock timer, second authoritative store, or generated hand edits may be introduced.
6. A shared mutable path has one owner and is integrated serially. Disjoint paths in the same wave may proceed in parallel; the integration owner still consumes their published outputs in dependency order.
