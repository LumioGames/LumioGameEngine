## 提示词正文

你是一名资深的游戏服务器 / 网络引擎架构分析师。你手上有一份 **Unreal Engine 引擎源码**，路径在 `<UE_SOURCE_ROOT>`。任务是对 **UE 的 Dedicated Server 与网络栈**做一次**源码级**解剖，产出一份「每条论断都能指到文件与行号」的报告。

这不是从零开始的调研。委托方已经有一份**文档级预研**（下称「预研」），它把 UE DS 的分层、设计哲学、社区共识、反向教训写了个框架——**那些你不需要重做**。但预研有两个硬伤：

1. **它读不到函数体。** 所以「`ServerReplicateActors` 到底怎么排序和截断」「可靠队列溢出在哪一行踢连接」「控制消息的确切序列」全都停在 `Reported`。
2. **它太薄。** 五份姊妹调研里 DS 那份只有别人的三分之一。**录像与回放（H）、安全与信任边界（K）几乎没写开**，而这两块恰恰是源码里最实在的部分。

**这一波要同时干两件事：把 `Reported` 变成 `Verified-Src`，以及把写薄的地方按源码补厚。**

### 1. 这一波要什么

**一句话目标**：把「一个客户端的数据包打到服务器网卡」到「另一个玩家看见这次改动」的每一层，用源码坐标铺满——包括每一层的预算、每一层的失败路径、每一层的隐含前提。

具体四件事，按价值排序：

1. **逐条兑现预研的欠账**（第 4 节待证清单）——每条给源码级裁决：证实 / 证伪 / 部分成立 / 源码中不存在。
2. **把两张核心图钉在源码上**：① 一次连接建立的完整消息序列图；② 一次服务器复制循环的流程图。**预研只能画架构级的示意，本次要画成「每个框都标着函数名与行号」的版本。**
3. **把「名称待核」全部钉死。** CVar、`.ini` 段与键、控制台命令、宏、枚举全表——源码里都有确切答案，一次清干净。
4. **补厚预研写薄的章**：回放、安全与信任边界、失败与关闭路径、可观测性。这几块源码里全是硬料。

#### 1.1 明确不做的事（防跑偏）

- **不写使用手册。** 不要「如何打包 DS」「怎么配端口」「怎么上传托管平台」。
- **不做部署选型。** 选哪家托管、怎么灰度、运维流程怎么走——**明确不在范围**。判据仍是：「引擎在这件事上提供了什么抽象、这个抽象的形状对不对」→ 要答；「实际选哪家、怎么部署」→ 略过。
- **但「多版本共存 / 滚动更新 / 会话排空 / 断线重连」是重点问题**，不许被上一条误伤砍掉。UE 在这几件事上内置支持极弱——**「弱在哪、源码上表现为什么、生产项目补在哪个钩子上」正是本次最想要的答案之一**。
- **不重写预研**：不要再写一遍 UE 网络的历史、社区痛点清单、通用架构感想。只在源码给出新证据时才碰这些话题，且写成「预研说 X，源码显示 Y」的对照形式。
- **不评价委托方的设计。** 第 3 节那张画像是参照系，不是评审对象。

#### 1.2 与 GAS 源码分析（姊妹篇）的边界

有另一位执行者在同一份源码上分析 **GAS**。分工：

### 2. 硬性规则（违反即退回重做）

**R1. 证据坐标格式（本次的核心纪律）**

每条源码级论断必须给出三件套：

```
<相对 <UE_SOURCE_ROOT> 的路径>:<起行>-<止行> · <符号名>
```

例如：`Engine/Source/Runtime/Engine/Private/NetDriver.cpp:3820-3910 · UNetDriver::ServerReplicateActors_PrioritizeActors`

- **路径必须相对引擎根**，不要带 `<UE_SOURCE_ROOT>` 前缀。
- **行号与符号名必须同时给。** 行号随版本漂移，符号名是重新定位的锚点。**只给行号不给符号名 = 不算数。**
- 引用配置项时给 `.ini` 文件路径 + 段名 + 键名；引用 CVar 时给注册点坐标。

**R2. 置信度四级**

| 等级 | 含义 | 门槛 |
|---|---|---|
| `Verified-Src` | **你亲自打开文件读到了实现** | 必须带 R1 三件套 |
| `Verified-Doc` | Epic 官方文档 / 源码注释明文 | 给 URL 或注释坐标 |
| `Reported` | 社区一致但未核一手 | 给来源与版本 |
| `Estimated` | 推断 | **必须写清推断依据** |

**红线：读了头文件里的声明 ≠ 读了实现。** 任何关于**先后顺序、条件分支、循环、错误处理、预算截断**的论断，必须读到 `.cpp` 函数体。

**红线：重章（T4 / T5 / T6 / T10 / T11）里 `Verified-Src` 必须占多数论断。** 某章写完全是 `Reported` = 这章没做。

**R3. 禁止编造，禁止用记忆代替读盘**

- 不得凭记忆写类名、函数名、宏名、CVar 名、`.ini` 段名、枚举值、控制台命令、版本行为、路径、行号。**每一个都要 grep 到才写。**
- 预研提到但**源码里不存在**的东西，本身就是重要发现——写进勘误章。
- 记不准就写 `[未在源码中找到]` 并写明搜索过程。**一个诚实的空白远比一个自信的错误有价值。**

**R4. 版本必须钉死（第一件事）**

- `<UE_SOURCE_ROOT>/Engine/Build/Build.version` —— `MajorVersion` / `MinorVersion` / `PatchVersion` / `BranchName` / `CompatibleChangelist`
- 若源码是 git 仓库：`git -C <UE_SOURCE_ROOT> rev-parse HEAD` 与最近一次提交信息
- 关键插件的 descriptor 成熟度字段（Iris、ReplicationGraph、NetworkPrediction、WebSocket 相关插件——**逐个读 `.uplugin`，不要凭印象说谁是 Experimental**）

**所有行号相对同一版本。** UE4 与 UE5 行为不同处分别标注，不要混写。

**R5. EULA 约束：不得整段粘贴源码**

- **允许**：自述机制、引用符号名与坐标、≤ 10 行关键片段（注明坐标）、伪代码、流程图。
- **不允许**：整段复制、逐行翻译、把源码文件或其节选副本放进交付目录。

**R6. 数字要带条件**

带宽、连接数、包大小、队列深度、超时值——**引用源码里的常量时给坐标与它的编译期/运行期可改性**；引用实测数字必须带测试条件。拿不到就给**可复现的估算模型**（写清公式与每项假设）并标 `Estimated`。**绝对不要给一个没有来源的具体数字。**

**R7. 交付是写进仓库的文件，不是 zip**

见第 5 节。**只写文件，不要 `git add` / `commit` / `push`**，不要修改 `docs/research/README.md`。

**R8. 不得改动第一波的目录**

`<ARCH_REPO>/docs/research/2026-08-29-ue-dedicated-server/` 是外部交回物，正文保持原样。修正只能以你自己目录里的**勘误表**给出（T17 章 + `appendix/corrections-to-wave1.csv`）。

**R9. 区分「引擎提供」「引擎只给空接口」「纯社区惯例」**

每讲一个能力都要说清它属于哪一类，**用源码证明**（有实现 / 只有虚函数或空实现 / 源码里根本没有）。**把第三类说成第一类，是本次最严重的失真。**

### 3. 目标环境画像（用于判断可迁移性；自包含，不需要查任何委托方代码）

| 维度 | 目标环境的形态 |
|---|---|
| 项目形态 | 自研引擎的**体素大世界**。服务器权威模拟，客户端跑只读副本世界。近期目标：多个**浏览器**客户端登录同一个体素世界联机，挖 / 放方块实时互见。 |
| 语言与运行时 | **Rust 原生宿主**负责进程 / 网络 / 会话 / 传输；**C# 托管层**承载 Gameplay 语义；两层之间是稳定 ABI。**没有 UObject、没有引擎级 GC 对象图、没有蓝图 VM、没有 Actor 复制模型、没有 C++ 反射系统。** |
| 客户端形态（**硬约束**） | 客户端跑在**浏览器**里（.NET WASM）。**拿不到原生 UDP socket**：只能用 WebSocket / WebTransport / WebRTC DataChannel 这一类受限传输，且受同源策略、TLS 强制、连接数限制约束。**评估任何传输设计时必须带上这一条**——UE 的整套网络栈建立在「我有一个原生 UDP socket」这个前提上。 |
| 帧模型 | **固定步长、分相位推进的确定性逻辑 Tick**；一帧内有**唯一的提交点**；提交点之前的写入对复制与快照不可见，提交点之后重复执行必须幂等。 |
| 确定性诉求 | 可复现的求值顺序与**可计算的状态哈希**，用于回放、对账与崩溃恢复。**同一串输入必须产出同一状态**（Rust 权威实现与 C# 参考实现之间还要做差分测试）。 |
| 状态存储 | **ECS 是被复制的 Gameplay 状态的唯一权威存储**。世界实例分 `Authority` / `Replica` 两个角色，**各自独立的存储与实体命名空间**，通过身份映射对应。 |
| 契约模型 | **契约先行**：线协议由 Schema 生成，**字段集封闭**，两端都不得各自扩展载荷；序列化有**规范化字节**要求（同一状态在任何合规编码器上逐字节相同，用于哈希、校验与迁移）。 |
| 权威与预测 | 服务器校验并提交；客户端只能在**有界的预测窗口**内预测。ECS 状态、Ability 状态、体素覆盖层属于**同一个确认 / 回滚单元**。 |
| 故障模型 | Tick 内故障 **fail-stop**：不做字段级撤销，**整帧作废**，从快照 + 日志重建。 |
| 世界与流送 | 三维 Chunk 分块体素世界，存在**大规模写入**与区块流送；chunk 有驻留预算与驱逐栅栏。**铁律：缺失的 chunk 永远不等于空世界**，未加载 / 加载中 / 不可用必须显式上报。 |
| 持久化 | 快照 + WAL（前后哈希链）；写盘走 staging / 校验 / fsync / 原子激活，保留上一个有效检查点；恢复只重放**已认证且已提交**的记录。 |
| 发布与运维 | 发布目录按「产品 id + 发布 id」路由，**一个进程只装一个 Release**；当前要求**服务端与客户端 Release 精确匹配**。**多版本共存、滚动更新、会话排空、崩溃恢复**是明确的运维诉求。 |
| **尚未冻结** | **传输与编解码供应商、RPC / 消息分发模型、鉴权线协议、断线重连与恢复令牌、滚动更新的排空策略、耐久级别分档**——可靠通道与不可靠通道都还在桌面上。**本次结论会直接影响这几项选型。** |

#### T0. 基线、模块地图与读取纪律

- R4 要求的版本三件套 + 关键插件成熟度表。
- **网络相关模块的实际地图**：`Engine` 模块里网络相关文件的分布、`Sockets` / `Networking` / `PacketHandler` / `OnlineSubsystemUtils` 各自路径、Iris / ReplicationGraph / NetworkPrediction / WebSocket 类插件的实际存在与路径。**逐个确认，不存在的明确写「不存在」。**

- **检索日志**：实际用过的 grep 关键字与命中情况。

#### T1. 进程形态、权威判定与构建裁剪

- `ENetMode` 全枚举与 `GetNetMode()` 的实现；`HasAuthority()` / `GetLocalRole()` / `GetRemoteRole()` 的实际实现（**它到底判断了什么**）。
- Target 类型与 `WITH_SERVER_CODE` / `UE_SERVER` / `DEDICATED_SERVER` 一类编译期开关：**逐个给准确宏名与坐标**，说明它们的作用范围和渗透程度（grep 出现次数量级即可，标 `Estimated`）。
- 服务器侧裁剪：哪些东西是编译期剥离、哪些是运行期跳过、哪些必须手工标（cook 阶段的 server-only）。**漏标的后果在源码上是什么**（崩溃？空指针？静默降级？）。
- 单进程多世界 / 多房间：源码上是支持、勉强支持还是根本没考虑（看 `UWorld` 与 `UNetDriver` 的所有权关系、`GetWorld()` 的全局假设）。

#### T2. NetDriver / NetConnection / Channel / Bunch 逐层

- 三层职责切分与所有权关系（谁持有谁、生命周期谁管）。
- **Bunch 抽象（重点）**：`FOutBunch` / `FInBunch` 的字段、分片（partial bunch）的切分与重组规则、可靠 bunch 队列（`OutRec` / `InRec`）的结构与重传时机、按通道保序的实现。
- **待证：为什么可靠性建在 bunch 层而不是 packet 层**——从源码给出这个分层带来的确切能力（部分可靠、按通道独立保序、单通道阻塞不影响其它通道）与它埋的坑。
- **可靠队列溢出**：上限常量叫什么、多少、**溢出后走哪条路**（哪一行关闭连接、用什么关闭原因码）。预研把这条列为「脆弱性」但没有坐标——**这次钉死**。
- 包处理管线（`PacketHandler` 组件链）：链怎么构建（从哪个 `.ini` 段读）、握手 / 加密 / 压缩各挂在哪一环、**可插拔到什么程度**（换传输后端要动多少东西——用源码回答）。
- 位级序列化与量化：向量 / 旋转的压缩表示、`NetSerialize` / `NetDeltaSerialize` 钩子的调用点、**量化误差**的实际大小与它对一致性的影响。
- 每连接带宽 / 速率相关的配置项与 CVar：**准确名称 + 默认值 + 实际作用点坐标**。

**检索线索**：`NetConnection.h/.cpp`、`DataChannel.h/.cpp`、`NetDriver.cpp`、`FOutBunch`、`SendRawBunch`、`ReceivedNextBunch`、`PrepareWriteBitsToSendBuffer`、`RELIABLE_BUFFER`、`PacketHandler.cpp`、`NETCONNECTION_MAX_PACKET_SIZE`。

#### T3. 握手、控制消息与版本校验（**预研明确说没核到，本次必须钉死**）

### 8. 执行建议

**读法（省时间，照做）：**

- **先 grep 定位，再读文件。** `rg -n '<符号名>' <UE_SOURCE_ROOT>/Engine --type cpp --type h` 拿到坐标，再按行号区间读上下文。**不要从头读 `NetDriver.cpp` 这种上万行的文件。**
- **符号名优先于自然语言。** 搜 `ServerReplicateActors_PrioritizeActors` 远好于搜 `replication priority`。
- **先读头文件顶部的大段注释再读实现。** UE 的设计说明大量写在那里（`DataChannel.h`、`NetConnection.h`、`RepLayout.h`、`GameplayPrediction.h` 等），**比官方网站文档更坦白**。
- **顺着调用链读，不要按文件读。**
- **`.Build.cs` 与 `.uplugin` 是模块边界与成熟度的权威**，比目录结构和记忆可靠。
- **善用 `git blame` / `git log -S`（若源码是 git 仓库）**：一个奇怪设计的提交信息常常直接写着它解决的那个事故——**这是「每个设计背后都有一个坑」的最快挖法**，挖到就写进对应章的「意外发现」。
- **枚举全表用 grep 一次抓全**，不要一个一个想。
- 遇到「我记得好像是这样但搜不到」，**停下来标 `[未在源码中找到]`** 并写清搜索过程。

**推进顺序建议：**

1. T0（版本 + 模块地图）—— **必须最先做**，所有坐标的基准。
