## 会议裁决规则（Owner 拍板）

- **R1 · UE 优先 + 前提检查**：默认抄 UE（完全实践过、有商业积累）；但不完全照搬——每条进图前问「它的前提我们有没有」。前提成立→照抄结构；前提不成立（依赖原生 UDP / 变步长 / Actor 对象模型）→ 抄它的目标、换手段，并给出 UE 对应坑的坐标。
- **R2 · 核心原则**：性能优先、精简、第一性原理，框架尽可能简单；不重要的功能后续再加（标「留洞后加」），但框架必须完整。每条裁决标注「V1 必须 / 留洞后加」。
- **R3 · 边界着色（Owner 定位声明，裁决 17）**：DS 只做最底层核心模块并暴露接口；上层业务（复制语义、体素同步、玩法）是接口调用方，DS 不负责上层怎么用。
